# Linen runtime integration contract

Edition-owned TypeScript Worker. The maintained Base integration provides the installed Lobby at `/`, owner confirmation at `/setup`, and Linen at `/app`; this file describes Linen's domain API and data contracts, not proof that every integrated route has passed. Base authentication is bridged to Linen's existing native users, memberships, sessions and D1 records. Product and edition identities and applied migrations remain intact. Platform exports `AppEnv`, `Env`, `Principal`, `Role` from `src/platform/types.ts`. Principal is `{userId,workspaceId,roles}`; roles are owner/operator/employee/approver/hr/auditor/integration. Bindings: `DB` D1, `ATTACHMENTS` private R2, `SESSION_SECRET`, base64 32-byte `ENCRYPTION_KEY`; optional APP_ORIGIN and BOOTSTRAP_TOKEN. An unconfigured connection does not establish provider behavior.

Feature modules export `registerXRoutes(app: Hono<AppEnv>)`. The supplied app is mounted at `/api/v1`; register relative paths such as `/requests`. Authentication middleware precedes feature routes and sets `c.get('principal')`; no user or workspace comes from request parameters. All private mutations require same-origin Origin and `X-Linen-CSRF` equal to the authenticated session CSRF token. Public setup/login also require same-origin Origin. Always scope SQL by principal.workspaceId and additional participant/role/sensitivity rules.

Platform utility exports: `id()` UUID, `now()` UTC ISO8601, `ApiError(status,code,message)`, `jsonBody(c)` object parser, `requiredString(value,name,max?)`, `requireRole(c,...roles)`, `audit(c,action,target,detail?)`. Error JSON is `{error:{code,message}}`. Success is normal typed JSON. No generic success wrapper. D1 prepared SQL binds scalar values; use atomic batch for coupled changes and conditional revision updates. Dates are ISO UTC strings; IDs UUID strings. JSON columns end `_json`; workspace references use `workspace_id`. Domain authors own their schema.

Platform schema 0001: workspaces(id,name,created_at), users(id,email,name,password_hash,created_at), memberships(workspace_id,user_id,roles_json,active), sessions(id,user_id,workspace_id,token_hash,csrf_token,expires_at,created_at), audit_events(id,workspace_id,actor_id,action,target,detail_json,created_at), connections(id,workspace_id,provider,name,config_json,secret_ciphertext,status,revision,created_at,updated_at), workspace_settings(workspace_id,settings_json,revision). Sessions and connection secrets are never returned in exports. Separate feature migrations: 0100–0199 work, 0200–0299 execution, 0300–0399 services, 0400–0499 intelligence, 0500–0599 operations.

The edition's domain API remains `/api/v1`: GET `/setup`, POST `/setup` (first owner; once only), POST `/login`, GET `/session`, POST `/logout`, GET `/workspace`, GET/POST/PATCH `/members`, GET/PATCH `/settings`, GET/POST/PATCH/DELETE `/connections`. This API setup endpoint is distinct from the Base owner-confirmation page at `/setup`. GET session returns `{principal,user,workspace,csrfToken}`. Setup/login set the Linen native session cookie; fetch GET session afterward for the CSRF token and identity. The domain API setup accepts `{email,name,password,workspaceName,bootstrapToken?}`. Login accepts `{email,password}`. Maintained source origins and revisions are recorded in edition metadata and source-lock records. The public source repository is [just-every/run-linen](https://github.com/just-every/run-linen).

Private R2 support is `signAttachment(c,key)` and `verifyAttachment(c,key,expires,signature)` from platform/attachments. Domain routes must first check record visibility and map its key; keys start `${workspaceId}/`, signatures bind current user/workspace and expire in five minutes. Do not expose a public bucket or accept a user-provided key without its record scope. Domain attachment routes own bytes and metadata.

Optional POST `/sso` verifies actual Cloudflare Access RS256 JWT against installation `ACCESS_ISSUER` and `ACCESS_AUDIENCE`, then matches an existing active member. It never grants roles. External SSO requires a real configured Access application; absent config returns 503. ISO UTC timestamps remain the chosen storage contract to avoid locale/DST ambiguity; expiry comparisons use explicit Date parsing.

POST `/password` accepts `{currentPassword,password}`, revokes all user sessions and returns a new cookie; refetch session for its new CSRF token. Public bootstrap refuses non-localhost origins unless BOOTSTRAP_TOKEN is configured. Login rate limits persist in D1. Connection `config` accepts only nonsecret string fields tenantId/tenant/domain/baseUrl/issuer/audience/clientId/scope/region/mailbox/description; secret tokens belong in encrypted `secret`. Privileged writes and their audit entry commit in one D1 batch.

Refresh maintained-source locks after intentional changes and verify them before source publication. Retained source pins preserve assembly intent; deployment is separate from source publication. Maintainer-only `pnpm test:platform` uses an isolated real workerd/D1/R2 test worker; `LINEN_TEST_EMITTED=1 pnpm test:platform` checks the compiled application API without test-only R2 routes. These are developer tests, not installed-edition commands, and results must be recorded against the exact integrated source before claiming a pass.
